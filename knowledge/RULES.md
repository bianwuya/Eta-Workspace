# Eta工程规则与决策

此页仅维护仍有效的工程契约。当前任务决定目标和副作用范围；背景记忆、Skill和旧任务许可不升级为新授权。通用维护纪律见工作区Skill `project-maintainer`，日常流程见[ITERATION](ITERATION.md)。

## 个人版与代码边界

- **官方优先、增量优化（用户 2026-11-12 明确确立的最高工程设计原则）**：以当前已验证的 Eta 官方源码为功能和架构基准；官方已有且满足目标的功能、组件、状态机、Runtime、子代理和 UI，直接使用官方实现。个人实现与其重复时，优先删除个人重复代码及其接线/测试，不能长期保留两套相同机制；不得因为个人代码先写就覆盖官方。
- **官方不足才增量**：仅对用户明确需要、官方尚未覆盖且有可复现缺陷或验收用例的边界场景加最小扩展，优先复用既有组件/扩展点与 local 目录，集中修改点而非大面积侵入官方。用户原已明确要保留的能力不因“官方优先”被误删（主/子代理缓存稳定与安全接续、具体模型/Token/缓存统计、设置页统计、自定义压缩模型/提示词、手动排序与安全降级、独立生图、必要中转兼容）。
- **删除必须先证明重复**：逐项以官方版本 SHA、文件/调用点、功能等价性、用户保留清单和测试证据建矩阵；确认官方已覆盖后，在独立受控工作树删自制重复功能、依赖、路由和死代码。不可整目录覆盖或误删其他功能；必须验证回归、数据迁移与反向依赖。未经证明是否等价的差异先保留和标注 REVIEW，不能仅因文件名/功能名字相同就删。
- 官方同步/准备上游PR/合入时间由用户决定，不恢复定时或普通PR联动的上游集成。main 保持纯上游，local 为稳定个人版，新增工作进入隔离功能分支；源码与资产分仓保持。触及>=5个既有上游文件需重新评估必要性；不重写共享历史凑提交。
- 不用本地功能名重写versionCode/versionName；构建元数据区分实际源码，文档HEAD不能冒称APK源码。保留包名、原签名、原测试/Lint，不吞异常/取消或无条件成功。
- 代码/必要需求可按用户已有适用推送偏好进入指定仓库供审查；本次只读/本地/不push要求优先。资产WIP与敏感资料不随之上传；远端业务合入、安装、公开性/保护/Secrets/发布是独立决定，不默认强推或改规则。
- 快速来自减少无关调查、复用证据/工具链，不来自弱化测试、删必要指令或自动化扩大范围。不建常驻监控、无限重试、新调度框架；内部类型化数据不层层重复防御，外部Intent/URI做好真实边界验证。

## 前端契约

- **长期前端审美与官方复用硬规范（2026-11-12 最新）**：生产 UI 必须优先复用 Eta 官方已有组件与布局，MIUIX/COUI 分别复用真实样式、主题 token、导航/设置项/动画，不用自绘仿官方组件或 GPT 主观审美重新配色、圆角、字体、层级、转场。若官方已覆盖，个人重复实现应删除；官方不足才做边界增量。审美聚焦信息层级、真实视觉焦点、对齐、可读与触达，不靠增加装饰。
- **快速预览审核前置**：纯逻辑/文案且不造成可见 UI 变化可按授权直接实施；新增界面、明显布局或动画改变必须先提供一次可审预览，列清官方组件映射、主视觉焦点、关键状态、MIUIX/COUI 与浅深色、手势/转场；用户明确批准范围后才能进入正式 UI 实现。已批准区域不可反复推翻；未经批准只可修改设计/隔离预览，不碰正式业务 UI。预览不得冒充真实 Compose，HTML 只能说明结构；真实动画/手势最后必须动态验收。未经本人要求不另配色，不缩小全部文字掩盖问题，不自动消耗生图额度。
- **唯一可用的 Windows 前端 Skill 路径**：`F:/eta/02-工程知识库/skills/frontend-layout/SKILL.md` 及 `references/COMPONENTS.md`、`REVIEW-GATES.md`、`MOTION.md`、`APPROVALS.md`。先按任务读取并记录组件/预览/批准依据；旧 `/workspace/skills/frontend-layout` 在当前 Windows 本机未找到，不得冒称已读取。历史获批视觉原图未定位时不能编造批准资产。保留认可部分，不让用户重复纠错；只在确有实际收益时派专职前端 Agent。
- 会话选项面板与输入区为同组，继承同类外壳/圆角/阴影、对齐与稳定间距；提问不为紧凑删状态/内容。历史存在 v2 认可记录，但当前 Windows 未找到旧 `frontend-layout/references/examples.md` 原件；在找到并验证原件前不得把其具体尺寸/配色或批准范围写成现行可用事实。新批准资产登记到 `frontend-layout/references/APPROVALS.md`。
- 动态验收独立：原导航进入/返回、圆角裁剪过程、状态保持、浅深主题及自动跟随/手动恢复、弹层/系统栏、长截/性能。编译或接入NavDisplay不等于真实观感通过；本人失败反馈不能用旧单测或“没安装”反驳。

## 模型输入、协作与产品边界

- 维持system/工具/旧历史稳定前缀、原session/账号/cache绑定，队列引导在完整turn边界追加，不取消在途请求再重建。图文复用实际摄取/FD链，不把DOM/字体/图片Base64回灌模型历史；实际缓存只用usage证据。
- 子代理沿当前公开工具与已实现协议。accepted是启动不是完成，主助手可继续独立工作；自然结束后无轮询等报告/新输入。语义终态与引擎终态、组/INFO/关键请求、恢复边界见代码/LESSONS；不复活被否定的邮箱/预算监督调度框架。后续用户批准的功能不能被旧历史“一律同步”阻断。
- 压缩采用用户已批准的完整待压缩历史单次摘要；独立配置、无摘要字符上限、容量不足不截断/不提交原历史。旧分段/原文分片/二次合并方案已撤销，不因历史测试绿恢复。
- 分享/拖放只追加真实主聊天草稿，保留原文字，不自动发送；临时URI先稳定复制再释放权限。扩大到语音独立进程/其他悬浮宿主要有具体需求与验收，不把未实现范围当已支持。
- Codex多账号为手动选择，无自动轮换/额度轮询/失败换号；单请求固定账号，刷新/重试不跟随UI换号，跨账号重放边界与Keystore凭据保持。具体证据见原任务/代码，不在核心保存账号槽或凭据。

## GUI工具与虚拟屏合同

沿当前公开工具schema/原作者实现与内置提示使用已有后台虚拟屏、预览和智能画布，避免无故打断主屏；不另设一律virtual、强制路由或常驻胶囊规则。`launch_app`可按实际schema选择display，`open_uri`不传display；observe_screen取得操作权，release或接管后旧观察失效。旧“observe_screen不持操作权”“预览消失已定性不必查”已撤回，新异常按实时证据判断，不以历史猜测跳过诊断。此处只保留纠偏入口，细节和允许工具以当次公开合同为准。

## 维护与可恢复性

- 计划写专用任务路径，压缩前保存完整目标/必要约束/路径/已做未做/最新纠偏/下一步；索引只导航。不把某一旧批HANDOFF指定为所有新任务入口。
- STATE分开记录本地/远端/安装/交付/本人验收；LESSONS只写可复用原因/修复/证据。当前主助手修唯一主条目、废止冲突指南，不在页尾再追加反说法；工程收尾默认不写全局记忆流水。
- 当前电脑编译/单测/Lint 优先 WSL2 `Eta-Test-20261112` 的 ext4 工作树，Windows 入口用于原签名双包和补充检查，准确环境合同见根 AGENTS 与 WINDOWS。手机 ARM64 路线只在已核实的旧手机工程中使用；云非本地前置。文档不编 APK；标准原签名双包、本人手测与不自动安装承载会话 Eta 边界不变。
- 内置备份不是工作区/Skill/整个系统镜像；换签名/卸载导致的AndroidKeystore丢失不能靠文件恢复。禁止递归chown Linux rootfs，不重跑一次性旧迁移脚本；恢复时才读MIGRATION。
- AGENTS/Skill是读取约定，不是硬保证/沙箱；Root文件工具、UI条件写与工具revision是不同机制。没有复现或明确需求不新增规约；检查器不替代语义/权限/真实验收。

## Codex 前端原生派发（用户明确约定，2026-11-11）

当用户在 ChatGPT 确认“派发任务”时，由主助手直接通过远程电脑工具向**已经在电脑上运行的 Codex 桌面版**派发；不要求用户复制/粘贴、重新登录个人订阅、额外确认“要不要派发”。有对应 Git 工作区时将 Codex 新会话绑定到该工作区（隔离 WIP 时用相应 worktree），**必须能在 Codex 原生前端查看具体会话、执行中消息、工具调用、完成结果**，不能擅自另造独立可视化面板。优先 Codex 原生会话方式；仅通过后台 `codex exec` 启动且不确认前端可见，**不算满足前端派发要求**。Codex 官方 deep link `codex://threads/<id>` 可打开已有会话，但 CLI source=exec 在侧边栏稳定显示尚有兼容问题；每次派发须核对前端可发现性，出现阻碍应明确报告，不能冒称可视化已生效。不得与 OpenCode/Claude 混淆，除非用户明确另指定。使用电脑已配置的 Codex 提供方/额度，不静默改模型和授权，必要的付费、权限、覆盖/合并保护仍按原工程规则执行。

## Codex 文件夹信任的自动处理（2026-11-11 实测）
当用户明确确认将任务派发到其指定的本机工作区时，可通过 Windows UI Automation 在 **Codex 原生桌面版** 内处理“信任此文件夹吗？”提示。执行前必须从弹窗读取并校验**精确的文件夹绝对路径**与目标工作区一致，明确确认是 Codex 文件夹信任、不是 Windows UAC 或其他安全授权；只对用户已指定且可验证的工程目录操作，不对未知路径一律信任。2026-11-11 已实测自动点击信任一处独立的空测试目录，界面从信任确认切换到项目编辑器，不需要用户手点。此操作不等同模型执行授权，也不得自动升级为 danger-full-access、自动批准所有工具或安装操作。若出现路径不一致、权限扩大或不同内容的安全弹窗应停止并报告。

## 重要纠偏：Codex 派发不得抢占 Windows 前台（2026-11-11 实测）

用户反馈：以前用 \`codex://new?prompt=...&path=...\` 在派发任务时，强制把 Codex 窗口置于前台，干扰用户操作。**之后默认禁止通过这种方式派发。**禁止为可视化而自动弹出/激活 Codex，禁止自行操作用户当前键盘焦点。

**优先后台复用既有原生前端会话**：2026-11-11 已实测，使用本机同版本 Codex \`queue --thread <existing-Codex-Desktop-thread-ID> --message <task> -s read-only\`，成功把测试消息加入桌面版创建的原有会话（session 01a1cb4f-46f8-7d31-aa4c-10a9b871dba1，返回 BACKGROUND-OK，task_complete），未调用 App 激活/深链接。任务写入现有 Codex 会话且可在原生桌面版回看。优先走 \`F:\eta\02-工程知识库\tools\codex_background_dispatch.py\`，通过只读的 Codex state DB 查找 \`source=vscode\`、\`originator=Codex Desktop\` 且 cwd 与指定工作区**完全一致**的会话后调用 \`codex queue\`；不同工作区绝不可误派。脚本经 \`py_compile\` 和指定原生前端线程的 \`--dry-run\` 验证。

**当前限制**：\`queue\` 只能向**已经存在**的会话派发；如果某工作区尚无原生前端会话，宁可明确报告该限制，也不能暗中调用会抢前台的 \`codex://new\`。独立的 \`codex app-server thread/start\` 可执行，但前端可视性尚未可靠验证，因此不能拿它冒充符合 UI 要求。只有用户明确要求立即弹出新会话时，才允许显式激活 Codex。

不要为解决抢焦点再另造可视化面板，保留 Codex 原生前端呈现。普通 Codex 文件夹信任的自动处理仍以实际弹窗路径核对为前提，但不得因此主动抢前台。除非用户要求，不应在回答期间多次启动 Codex。

## Codex 派发选路优先级（2026-11-12，覆盖前面仅按 cwd 复用线程的策略）

当用户确认派发任何任务时，首先在 Codex 桌面版已注册的工作区中定位最合适的对应工作区。按明确工作区名、给定真实路径与最长已注册工作区根路径匹配；不基于关键词胡乱创建项目或将任务归入无关项目。匹配信息来自 Codex 本机 state_*.sqlite 的 projects 与 project_roots，只读查询。匹配程序位于 F:\eta\02-工程知识库\tools\codex_project_router.py，已验证 eta、easycli 插件维护计划和无项目 fallback 能正确区分；重复根目录显示歧义而不乱派。

有对应工作区：创建属于该工作区的独立 Codex 原生会话并提交任务，优先保持任务间上下文隔离；用户明确表示“继续之前任务/会话”时才向正确线程用 codex queue 后台追加。不得仅因为根目录相同，就把不同的新任务塞进老会话。

无对应工作区：创建“普通新聊天”（不关联任何已有项目）并提交任务，绝不随机使用某个无关项目的老会话，也不自动新建工作区。“随便的新聊天”是普通的、独立的新 Codex 对话，不等于随机挑选已有对话。

不抢焦点约束保留且优先：默认不得用 codex://new 强行置顶或突然夺取键盘输入焦点。新建前端会话的非抢焦点技术尚未端到端验证，若当前版本无法满足，则明确告知“选路已确认但前端后台新建受限”，不可谎报已派发，也不可默默改走不可见的 CLI 会话。只有用户明确同意前台弹出时，才可使用会切前台的方案。测试和路由规则更新不等于实际派发开发任务。

所有正式派发要求可在 Codex 桌面原生 UI 看见任务状态；成功不能仅凭本地进程退出码判断。额度仍使用电脑 Codex 当前模型提供方，不自动登录用户个人订阅。
