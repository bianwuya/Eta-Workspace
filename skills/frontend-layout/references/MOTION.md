# Eta 动画与过渡合同

## 官方优先
- 复用原生 Miuix/COUI 组件反馈、Scaffold、导航/Modal、现有 Compose animationSpec；没有同类实现时才局部补充。
- 真实交互需要实机、模拟器或 Compose Interactive/Animation Preview 验证；静态 HTML/截图不能验证触摸抢占、系统返回或手势惯性。
- 同一交互同一组件的进入/退出应镜像或符合已有官方行为，禁止突变方向和尺度；主页面长列表不得触发整页重布局。
- 选择状态、滚动、弹窗、侧滑、导航切换等动效不得破坏当前运行任务或正在输入的文本。

## 每一个转场必须填写的小型合同
```text
页面/组件：
官方参考与具体调用位置：
触发：点击/系统返回/拖动/模型状态变化...
初始态 / 运动中 / 终态：
动画起源与方向：
沿用哪个官方 motion spec：
时间/缓动：来自源码（写具体位置），无标准则说明新增依据
过程中的点击/输入/中断：
可逆、取消、快速连点行为：
小屏/大字体/系统动画缩放关闭时的退化：
验收证据：Animation Preview/录屏/关键帧截图/真实设备
```

## 重点案例
- 页面导航：从同一导航容器进入和返回，正确处理物理/手势返回；不要给所有页面随意增加弹跳。
- 弹窗：出现/消失使用对应主题原生弹窗；键盘弹出时内容和操作区始终可见，不靠盖住信息或溢出屏幕。
- 选项/卡片：复用 EtaChoiceChip 等既有反馈；变化应体现“响应已发生”，避免所有控件都渐变/缩放。
- 子代理状态：Running/Completed/Failed 的状态变化不抖动、不连续闪烁，统计数字更新不触发无意义容器伸缩；注意内容可读性。
- 图片放大：以官方 ChatImageViewer 手势和动画为基线，不再独立发明 pinch/double-tap/back 规则。
- 加载、断网与恢复：内容稳定，不出现“空页面 → 整页重排 → 有数据”的大跳变；失败可恢复的操作应有确定视觉反馈。

## 审核预览最省时的输出
- 普通切换：3 帧（开始/中间/结束）+ 简短过渡契约即可。
- 与手势/层叠相关：展示 5–12 秒内的真实录屏或可交互 Compose Preview，附 2 种边界操作。
- 改动只是颜色/字体且复用官方组件时：直接沿用组件原动画，无需额外录制。
- 人工只审核一次状态关系；后续参数微调交由代理按照已批准的同类标准完成，禁止每帧请用户确认。
