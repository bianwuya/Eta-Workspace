# 状态、知识与 Skill 维护协议

先按[环境路由](ENVIRONMENT.md)核实目标。适用于整理本次知识、更新过期入口、维护已有自定义Skill；纯业务修复不必读所有历史材料。

## 最小闭环

1. 只读盘点命中入口、冲突和必要证据；列出真实缺口，区分历史、最后观察和本轮实时采样。
2. 说明修改/保留项，备份将改文本及hash；保留其他WIP与staging，不为了整理复制ZIP/数据库/照片整树。
3. 在事实拥有者处纠正，不追加相反指南。修改前重读并核对hash，有并发变化先合并理解。
4. 只验证变更：文档链接/JSON，脚本对应隔离测试，主源/受控引用一致性；不为文档重建APK或重测业务。

## 各层只拥有一类事实

| 层 | 内容 | 不保存 |
|---|---|---|
| AGENTS | 稳定边界与项目路由 | 每轮进度或旧批准的延续 |
| INDEX/KB | 主题到权威来源 | 第二份安装/版本状态 |
| STATE/CURRENT | 继续入口，解释证据关系 | 改写历史构建或重复观察字段 |
| 最新观察 | 带对象、身份、来源、时间/boot、范围的事实 | 自动冒称实时或永久状态 |
| release/result/trace | 原构建/请求快照 | 后续部署的新事实 |
| 交付索引 | 文件位置、包身份、快照指针 | 与观察竞争的installed布尔值 |
| Skill | 可复用流程、判断与加载路线 | 单版本hash/日志流水或猜测 |

观察时间与整理时间分开；未知时间/boot用null，不补造。文件在、CRC/清单通过、安装完成、镜像完整、重启挂载、进程读取、算法执行、输出与体验逐层报告。单个JPEG成功不证明特定算法或所有优化；库mapping只证明映射。

制包快照installed=false与后来pending/已运行可同时为真。保留快照，更新唯一观察和CURRENT解释。安装树经过修复但未重新制包时，旧ZIP不能当作可重装修复版。

## 技能来源与分发

电脑知识与维护Skill主源在版本化资产仓；手机自定义Skill在App私有目录。外来技能的可用方法按需吸收，不全量覆盖现有规范，不新增相同触发的第二Skill。内置Skill不改。

写后依次核实：目标文件/hash/frontmatter → 实际App UID可读正文和资源 → 原生列表发现/启用 → 原生正文和资源读取。没有Eta原生工具时，只报告文件/App可读层，不猜刷新广播、不改registry、不强停承载会话的Eta。详见[发布与刷新](../assets/ACTIVATION.md)。
